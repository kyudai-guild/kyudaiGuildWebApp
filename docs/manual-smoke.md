# 手動スモークテスト手順書

> リファクタの各フェーズ後・デプロイ前に実施する最低限の動作確認。
> 所要時間: 約10分。ローカル（`npm run dev` → http://localhost:3000）またはVercelプレビューで実施。
> テストには「九大メールの一般アカウント」と「管理者アカウント（profiles.role = 'admin'）」の2つが必要。

## 1. 認証

| # | 手順 | 期待結果 |
|---|---|---|
| 1-1 | 未ログインで `/auth` を開き、九大メール以外（例: `test@gmail.com`）で**新規登録** | 「九州大学のメールアドレスのみ登録できます」等のエラーで拒否される |
| 1-2 | 九大メール（`@s.kyushu-u.ac.jp`）で新規登録 | 確認メール送信画面が表示される（自動ログインされない） |
| 1-3 | 確認メールのリンクを踏む | `/auth/callback` 経由でログイン状態になる |
| 1-4 | ログアウト → 同じアカウントでログイン | 成功してホームに戻る |
| 1-5 | （Phase 4 以降）運営が Supabase に直接追加した**非九大メール**アカウントでログイン | **ログインできる**（ドメイン検証はサインアップのみのため） |
| 1-6 | 誤ったパスワードでログイン | エラーメッセージが表示される（内部エラーコードが露出しない） |

## 2. 保護ルート

| # | 手順 | 期待結果 |
|---|---|---|
| 2-1 | 未ログインで `/my-quests` に直接アクセス | `/auth` にリダイレクト |
| 2-2 | 未ログインで `/admin` に直接アクセス | `/auth` にリダイレクト |
| 2-3 | **一般アカウント**でログインして `/admin` にアクセス | ホーム（`/`）にリダイレクト（管理画面が見えない） |

## 3. クエスト

| # | 手順 | 期待結果 |
|---|---|---|
| 3-1 | 一般アカウントでホームの「クエストを申請」からクエスト作成 | 成功メッセージ。掲示板には**まだ表示されない**（pending） |
| 3-2 | `/my-quests` を開く | 3-1 のクエストが「審査中」バッジで表示 |
| 3-3 | 管理者で `/admin` → クエスト審査タブ → 3-1 を**承認** | 承認済みに変わり、掲示板（`/#quest-board`）に表示される |
| 3-4 | 別の一般アカウントで掲示板からそのクエストに**応募** | 応募成功。同じクエストに2度目の応募はエラー |
| 3-5 | 自分のクエストに自分で応募 | エラーで拒否される |
| 3-6 | 管理者でリジェクト（理由を空にして実行） | 「リジェクト理由を入力してください」エラー |
| 3-7 | クエスト申請者が `/my-quests` で応募者を確認 | 3-4 の応募者が表示される |

## 4. イベント

| # | 手順 | 期待結果 |
|---|---|---|
| 4-1 | 一般アカウントで `/events` を開く | カレンダー/リスト表示。**登録ボタンが表示されない** |
| 4-2 | 管理者で `/events` → イベント登録 | 即座にカレンダーへ反映される（審査なし） |
| 4-3 | ホーム（ログイン状態）を開く | 直近イベントのリストに 4-2 のイベントが表示される |
| 4-4 | カレンダーの月送り／カテゴリ色 | 月フィルタが機能し、カテゴリごとの配色が付く |
| 4-5 | 未ログインでホームを開く | イベントリストではなくキャッチコピー＋ログインCTAが表示される |

## 5. ページ巡回（クラッシュ・404確認）

未ログインと管理者ログインの両状態で以下を開き、白画面・クラッシュ・レイアウト崩れがないこと:

- `/` （ホーム）
- `/auth`
- `/events`
- `/my-quests` （要ログイン）
- `/admin` （要管理者）

スマホ幅（DevTools で375px）でも `/` と `/events` を確認する。
