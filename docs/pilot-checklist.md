## A. 事前に必ずやること

### A-1. 【最重要】LINEログインチャネルの公開ステータス

LINEログインチャネルは作成直後 **「開発中」** で、この状態では
**Admin または Tester 権限を持つ人しかログインできません。**
参加者が「LINEでログイン」を押しても失敗します。

どちらかを選んでください。

| 方法 | 手順 | 備考 |
|---|---|---|
| **参加者をTesterに追加**（少人数向け） | チャネル → 権限管理 → メールで招待（Tester） | 各自**ビジネスIDとLINEアカウントの連携**が必要。人数が多いと手間 |
| **「公開済み」に変更**（推奨） | チャネル基本設定 → ステータスを公開済みに | **一度公開すると「開発中」に戻せません**。公開前にプライバシーポリシーURLの用意を求められる場合があります |

☐ 対応済み

> LINE連携を使わないなら後回しでも構いませんが、その場合は参加者に
> 「LINEでログインは今回使えません」と事前に伝えてください。

### A-3. Vercel の本番ブランチと環境変数

- ☐ **Production Branch** を、パイロットで使うブランチに設定（Settings → Git）
- ☐ 独自ドメインが**本番デプロイ**に割り当たっている
- ☐ 環境変数を **Production スコープにも**設定してRedeploy

> cron（日次ダイジェスト）は**本番デプロイにしか実行されません**。
> プレビューのままだと通知が自動配信されません。

### A-4. Supabase のメール送信レート制限

☐ **Authentication → Rate Limits** で送信上限を引き上げる

既定は **1時間あたり30通**です。サークルのメンバーが一斉に登録すると途中で止まります。
参加人数の3倍程度を目安に上げておいてください（再送分を見込む）。

### A-5. 管理者アカウントと承認体制

☐ 管理者アカウント（`profiles.role = 'admin'`）が存在する
☐ **誰がいつクエストを承認するか**を決める

**クエストは管理者が承認するまで掲示板に出ません。** 承認担当が不在だと
「投稿したのに何も起きない」状態になり、テストが止まります。
パイロット中は「1日1回は確認する」程度の運用ルールを決めておいてください。

### A-6. テストデータの掃除

☐ テストユーザー・クエスト・イベントを一掃する

**`supabase/supabase_reset_test_data.sql` を使ってください。**
手順と注意点は `docs/admin-operations.md`（1. テストデータを消して、まっさらにする）にあります。

> ⚠️ 削除順序が重要です（quests・events を先に消さないとユーザー削除が外部キー違反で失敗します）。
> スクリプトはその順序になっているので、上から順に実行してください。

☐ 日次ダイジェストの初回で過去分が一斉送信されないようにする

```sql
update quests set line_notified_at = now()
where status = 'approved' and line_notified_at is null;
```

### A-7. どちらの案でテストするか決める

## D. 運営アカウントを共用メールアドレスへ移す手順

**サービスによって「正式な共同管理ができるもの」と「できないもの」があります。**
できるものは招待、できないものはパスワードマネージャで資格情報を共有します。

### D-1. 正式に共同管理できるもード（招待するだけ）

**Supabase**
1. ダッシュボード → 左上の組織名 → **Organization Settings → Team**
2. **Invite member** で共用アドレスを **Owner** として招待
3. 共用アドレスでログインし、招待を承認
4. 共用アカウントだけで操作できることを確認してから、個人を外す

☐ 完了

**GitHub**（推奨: Organization 化）
- 簡易: リポジトリ → Settings → **Collaborators** に共用アカウントを追加
- 本格: **Organization を無料で作成**し、リポジトリを Transfer。共用アカウントを Owner に
  → 代替わりしてもリポジトリが個人に紐づかないので、こちらが本来の形です

☐ 完了

**LINE Developers**
- プロバイダー → 権限管理 → **メールで招待**（Admin）
- 各チャネル（Messaging API / LINEログイン）でも同様に Admin として追加
- LINE公式アカウント（OA Manager）→ 権限管理 → 管理者として追加

☐ 完了

### D-2. 正式な共同管理ができないもの（資格情報を共有）

**Cloudflare（無料プラン）**

⚠️ **無料プランでは、招待した人は自動的に Administrator になり、Super Administrator にはできません。**
Administrator は DNS 等の設定は変更できますが、**メンバー管理と請求は操作できません**。
つまりドメインの支配権は、アカウント作成者（＝あなた）に残ります。

現実的な対応:
1. 共用アドレスを **Members から招待**（日常のDNS作業はこれで足ります）
2. **アカウントのログイン情報と2FAシークレットをパスワードマネージャで共有**
   ← ドメイン失効を防ぐには、これが実質的な引き継ぎ手段になります
3. 自動更新ONと支払い方法の有効期限を、引き継ぎ時に必ず確認する

☐ 完了

**Vercel（Hobbyプラン）**

Hobby プランにはチーム機能がありません。選択肢:
- **資格情報を共有**（当面はこれで十分）
- プロジェクトを共用アカウントへ **Transfer**（Settings の最下部にある移管機能。実施前に環境変数とドメイン設定の控えを取ること）
- Pro プラン（$20/月）にしてチームを作る

☐ 完了

**Resend**
- 無料プランはシート数に制限があります。**共用アドレスでアカウントを作り直す**のが確実です
  （ドメイン認証をやり直す必要がありますが、DNSレコードは同じものが再利用できる場合があります）
- 当面は資格情報の共有でも運用できます

☐ 完了

### D-3. 共通ルール

☐ 共用アカウントの **2段階認証は認証アプリ**にし、**シークレットをパスワードマネージャで共有**する
  （個人のスマホSMSにすると、その人の引退で全員が締め出されます）
☐ すべての資格情報をパスワードマネージャに集約し、複数人がアクセスできる状態にする
☐ **個人アカウントの権限は、共用アカウントだけで全操作できることを確認してから外す**
