# LINE連携 セットアップ手順書

> **状態**: コード実装済み（migration v7 + `/api/line/*`）。
> 動かすには**運営側でのチャネル作成と環境変数の設定が必要**です。この文書のとおりに進めてください。

## 1. できること（実装済みの機能）

| 機能 | 説明 |
|---|---|
| **LINE連携** | プロフィール画面の「LINEと連携する」→ LINEの同意画面 → 紐付け完了（ワンタップ） |
| **LINEでログイン** | 連携済みの人は、ログイン画面の「LINEでログイン」から**パスワード不要**で入れる |
| **クエスト通知** | 管理者がクエストを承認した瞬間、興味分野が一致する連携済みユーザーへ Flex Message を送信 |
| **通知ON/OFF** | プロフィール画面のトグルで本人が切り替え |
| **友だち状態の追跡** | Webhook で友だち追加/ブロックを検知し、送れない相手には送らない |

**九大生限定の原則は維持しています**: 新規登録は九大メール必須のままで、LINEは「登録済みアカウントに紐付ける」使い方です。未連携のLINEでログインしようとすると案内メッセージが出ます。

## 2. 【最重要】チャネル構成のルール

**LINEログインチャネルと Messaging API チャネルは、必ず同じプロバイダーの下に作ってください。**

LINEの `userId` は**プロバイダー単位で発行**されるため、別プロバイダーに分けると
「ログインで取得した userId」に対して「Messaging API からプッシュ通知が送れない」状態になり、
連携はできるのに通知だけ届かない、という分かりにくい不具合になります。

```
プロバイダー「九大ギルド」
├── LINEログインチャネル      → ログイン・連携に使用
└── Messaging APIチャネル     → 通知の送信・Webhookに使用
```

## 3. 運営がやる作業（この順で）

### 3-1. LINE公式アカウント（Messaging API）を作る
1. https://entry.line.biz/ でLINE公式アカウントを作成
2. https://developers.line.biz/console/ にログイン
3. **プロバイダーを1つ作成**（例: 九大ギルド）
4. そのプロバイダー内で、作成した公式アカウントの **Messaging API を有効化**
5. **Messaging API設定** タブで取得・設定する:
   - **チャネルアクセストークン（長期）** を発行 → コピー
   - **Webhook URL**: `https://<本番ドメイン>/api/line/webhook`
   - **Webhookの利用**: ON
   - **応答メッセージ**: OFF（自動返信を切る）／**あいさつメッセージ**: ON推奨
6. **チャネル基本設定** タブで **チャネルシークレット** をコピー

### 3-2. LINEログインチャネルを作る
1. **同じプロバイダー内**で「新規チャネル作成」→ **LINEログイン**
2. **LINEログイン設定** タブ:
   - **コールバックURL** に次を登録（複数行で登録可）:
     - `https://<本番ドメイン>/api/line/callback`
     - テスト用に使うURLがあればそれも追加
   - **リンクされたLINE公式アカウント**: 3-1で作った公式アカウントを選択
     （これで、ログイン時に友だち追加を促せるようになります）
3. **チャネル基本設定** タブで **チャネルID** と **チャネルシークレット** をコピー

### 3-3. Vercel に環境変数を設定
Settings → Environment Variables に以下を登録（**Production と Preview の両方**にチェック）:

| 変数名 | 値 | どこで取得 |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://<本番ドメイン>` | 自分で決める（**末尾スラッシュなし**） |
| `LINE_LOGIN_CHANNEL_ID` | 数字の羅列 | LINEログインチャネル → チャネル基本設定 |
| `LINE_LOGIN_CHANNEL_SECRET` | 英数字 | 同上 |
| `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` | 長い英数字 | Messaging APIチャネル → Messaging API設定 |
| `LINE_MESSAGING_CHANNEL_SECRET` | 英数字 | Messaging APIチャネル → チャネル基本設定 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabaseのservice_roleキー | Supabase → Settings → API |

設定後は **Redeploy が必要**です（環境変数は次のデプロイから反映）。

> ⚠️ **コールバックURLは完全一致**が必要です。Vercelのプレビューはデプロイごとにドメインが変わるため、
> `NEXT_PUBLIC_SITE_URL` に**固定のURL**（本番ドメイン、またはブランチ固定URL
> `https://<project>-git-<branch>-<team>.vercel.app`）を入れ、その URL をコールバックにも登録してください。
> ここが食い違うと `400 Bad Request` や「redirect_uri が不正」というエラーになります。

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` は **RLSを無視して全データを操作できる強力なキー**です。
> `NEXT_PUBLIC_` を付けない（クライアントに露出させない）こと、GitHubにコミットしないことを厳守してください。
> 本アプリでの用途は「LINEログイン時のセッション発行」と「通知対象の抽出」の2つに限定しています。

### 3-4. Supabase で SQL を実行
SQL Editor で `supabase/supabase_migration_v7_line.sql` を実行（v5実行済みが前提）。

## 4. 動作確認

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 九大メールでログイン → プロフィール | 「LINEと連携する」カードが表示される |
| 2 | 「LINEと連携する」をタップ | LINEの同意画面 → 友だち追加の確認 → プロフィールに戻り「LINE連携済み」 |
| 3 | ログアウト → ログイン画面 | 「LINEでログイン」ボタンが出る |
| 4 | 「LINEでログイン」 | パスワードなしでログインできる |
| 5 | 未連携の別LINEアカウントで 4 を実行 | 「まだ連携されていません」と案内が出る（勝手にアカウントが作られない） |
| 6 | プロフィールで興味分野に「プログラミング」を設定 | 保存できる |
| 7 | 管理者が「プログラミング」タグのクエストを承認 | 数秒でLINEに通知カードが届く |
| 8 | 通知トグルをOFF → 再度承認 | 通知が届かない |
| 9 | 公式アカウントをブロック → 承認 | エラーにならず、その人には送られない |

## 5. 通知の仕様

- **送信タイミング**: 管理者がクエストを**承認した時**（申請時ではない）
- **送信対象**: 「興味のある分野」がクエストに一致 かつ 連携済み かつ 通知ON かつ 友だち追加済み の人（依頼者本人は除く）
- **一致の判定**: 興味分野のラベルが「クエスト種別と一致」「タグと一致」「タイトルに含まれる」のいずれか
- **上限**: 1クエストあたり200人（無料枠の消費を抑える安全弁。`src/lib/quest-notify.ts` の `MAX_RECIPIENTS`）
- **送信方法**: multicast（1回のAPIで最大500人）

### 無料枠について
LINE公式アカウントのコミュニケーションプラン（無料）は **月200通**まで。
「通知を受け取る人数 × 承認するクエスト数」で消費するので、ユーザーが増えたら:
1. ライトプラン（月5,500円 / 5,000通）へ変更、または
2. 即時通知をやめて**1日1回のダイジェスト配信**に変更（カルーセルで複数件まとめる）

を検討してください。2 はコード側の改修が必要なので、必要になったら相談してください。

## 6. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 連携ボタンを押すと「LINE連携は準備中です」 | `LINE_LOGIN_CHANNEL_ID` / `SECRET` が未設定。設定してRedeploy |
| LINE側で「redirect_uriが不正」 | コールバックURLの登録と `NEXT_PUBLIC_SITE_URL` が不一致 |
| 「LINE連携の有効期限が切れました」 | 同意画面で10分以上放置。もう一度実行 |
| 連携はできるが通知が届かない | ①公式アカウントを友だち追加しているか ②2つのチャネルが同一プロバイダーか ③通知トグルがONか ④興味分野が一致しているか |
| 「LINEログインは現在利用できません」 | `SUPABASE_SERVICE_ROLE_KEY` が未設定 |
| Webhookが動かない | Webhook URLの末尾が `/api/line/webhook` か、「Webhookの利用」がONか確認。LINE Developers の「検証」ボタンで疎通確認できる |
