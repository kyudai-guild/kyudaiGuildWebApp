# LINE連携 セットアップ手順書

> **状態**: コード実装済み（migration v7 + `/api/line/*`）。
> 動かすには**運営側でのチャネル作成と環境変数の設定が必要**です。
> ※ 2026年8月時点の LINE Developers / LINE Official Account Manager の仕様に合わせています。

## 1. できること（実装済みの機能）

| 機能 | 説明 |
|---|---|
| **LINE連携** | プロフィール画面の「LINEと連携する」→ LINEの同意画面 → 紐付け完了（ワンタップ） |
| **LINEでログイン** | 連携済みの人は、ログイン画面の「LINEでログイン」から**パスワード不要**で入れる |
| **クエスト通知** | 管理者がクエストを承認した瞬間、興味分野が一致する連携済みユーザーへ Flex Message を送信 |
| **通知ON/OFF** | プロフィール画面のトグルで本人が切り替え |
| **友だち状態の追跡** | Webhook で友だち追加/ブロックを検知し、送れない相手には送らない |

**九大生限定の原則は維持しています**: 新規登録は九大メール必須のままで、LINEは「登録済みアカウントに紐付ける」使い方です。未連携のLINEでログインしようとすると案内メッセージが出るだけで、勝手にアカウントは作られません。

## 2. 【最重要】2つのチャネルは同じプロバイダーに置く

必要なチャネルは2つで、**必ず同一プロバイダーの下に揃えてください**。

```
プロバイダー「九大ギルド」
├── Messaging APIチャネル   → 通知の送信・Webhook（公式アカウントに紐づく）
└── LINEログインチャネル     → ログイン・連携
```

理由は2つあります。

1. LINEの `userId` は**プロバイダー単位**で発行されるため、別プロバイダーだと「ログインで得た userId」にプッシュ通知を送れません（連携はできるのに通知だけ届かない、という切り分けづらい不具合になります）
2. ログインチャネルと公式アカウントを**リンクする条件**が「同じプロバイダーに属していること」だからです

> **作成順序に注意**: Messaging API チャネルは**作成時にプロバイダーを選ぶ/作る**仕様なので、
> **先に公式アカウント側を作り、その時に決めたプロバイダーに後からログインチャネルを追加**するのが確実です。

## 3. 運営がやる作業

### 3-0. すでにある公式アカウントを使ってよいか判断する

手元に既存のLINE公式アカウント（Messaging API 有効化済み）がある場合、次の3つを確認してください。
**すべて「はい」なら再利用してOK**です。その場合 3-1〜3-4 は不要で、**3-5 から始められます**。

1. **管理者権限があるか** — チャネルと公式アカウントを**リンクするには両方の管理者権限が必要**です
   - LINE Developers → 該当チャネル → **権限管理** で自分が `Admin` か
   - LINE Official Account Manager → 設定 → **権限管理** で自分が「管理者」か
2. **他の用途で稼働していないか** — すでに Webhook URL が設定されていたら、**書き換えると元のシステムが止まります**。
   応答設定の変更も既存運用に影響します。誰かが運用中のアカウントは触らないこと
3. **本番でもそのアカウントを使い続けるか**

> ⚠️ **プロバイダーの選択は後戻りが高くつきます。**
> LINEの `userId` は**プロバイダー単位**で発行されるため、後から別プロバイダーのアカウントに移すと
> DBに保存済みの `line_user_id` がすべて無効になり、**連携済みユーザー全員に再連携してもらう必要**があります。
> テストユーザーしかいない今なら切り替えコストはほぼゼロなので、迷うなら**先に本番用アカウントを用意**してください。
>
> 切り替える場合は、連携情報をリセットしてから作業します:
> ```sql
> update profiles
> set line_user_id = null, line_display_name = null, line_picture_url = null,
>     line_linked_at = null, line_friend = false
> where line_user_id is not null;
> ```

### 3-1. LINE公式アカウントを作る

**LINE Developers コンソールから Messaging API チャネルを直接作ることは現在できません。**
公式アカウントを作り、そこから Messaging API を有効化すると、チャネルが自動生成される流れになっています。

1. https://entry.line.biz/ で **LINE公式アカウントを作成**（LINEアカウントかメールアドレスでビジネスIDに登録）
2. フォームに必要事項を入力するとアカウントが作られます
3. https://manager.line.biz/ （LINE Official Account Manager）で作成したアカウントを確認

### 3-2. Messaging API を有効化する（＝チャネルが作られる）

1. LINE Official Account Manager で対象アカウントを開く
2. 右上の **「設定」** → 左メニュー **「Messaging API」**
3. **「Messaging APIを利用する」** を実行
4. 初回のみ **開発者情報の登録**（名前・メールアドレス）が求められます
5. **プロバイダーを選択または新規作成**します
   → ここで決めたプロバイダーが、後でLINEログインチャネルを作る場所になります。**名前を控えておいてください**
6. 完了すると、LINE Developers コンソールのそのプロバイダー配下に **Messaging APIチャネル** が現れます

### 3-3. Messaging API チャネルの設定と鍵の取得

https://developers.line.biz/console/ → 該当プロバイダー → Messaging APIチャネル

- **「Messaging API設定」タブ**
  - **チャネルアクセストークン（長期）** を発行 → コピー（`LINE_MESSAGING_CHANNEL_ACCESS_TOKEN`）
  - **Webhook URL**: `https://<本番ドメイン>/api/line/webhook` を設定
  - **Webhookの利用**: ON（設定後「検証」ボタンで疎通確認できます）
- **「チャネル基本設定」タブ**
  - **チャネルシークレット** をコピー（`LINE_MESSAGING_CHANNEL_SECRET`）

### 3-4. 自動応答をオフにする

Botとして動かすので、既定の自動返信は切っておきます。

LINE Official Account Manager → **設定 → 応答設定** で:
- **応答メッセージ**: オフ
- **あいさつメッセージ**: オン推奨（友だち追加時の案内に使えます）

> 応答メッセージ/あいさつメッセージは LINE Developers 側の「Messaging API設定」タブからも
> 「編集」リンクで同じ画面に飛べます。Webhook のON/OFFはどちらの画面からでも設定できます。

### 3-5. LINEログインチャネルを作る

LINE Developers コンソール → **3-2で選んだプロバイダー** → 「新規チャネル作成」→ **LINEログイン**

作成時の入力項目（現行のフォーム）:

| 項目 | 設定内容 |
|---|---|
| チャネルの種類 | LINEログイン |
| プロバイダー | **Messaging APIチャネルと同じもの**（最重要） |
| **サービス提供地域** | 日本 |
| 会社・事業者の所在国・地域 | 日本 |
| チャネル名 | 例: 九大ギルド ログイン ※**「LINE」の文字列は使えません** |
| チャネル説明 | 任意の説明 |
| **アプリタイプ** | **ウェブアプリ** にチェック（これを選ばないとコールバックURLの設定欄が出ません） |
| メールアドレス | 連絡先 |
| プライバシーポリシーURL / 利用規約URL | 任意 |
| LINE開発者契約 | 同意にチェック |

作成後、続けて設定します。

- **「LINEログイン設定」タブ**
  - **コールバックURL**: `https://<本番ドメイン>/api/line/callback`
    （改行区切りで複数登録できます。テスト用URLがあれば併せて登録）
- **「チャネル基本設定」タブ**
  - **チャネルID** と **チャネルシークレット** をコピー（`LINE_LOGIN_CHANNEL_ID` / `_SECRET`）
  - **「リンクされたLINE公式アカウント」** の編集 → 3-1で作った公式アカウントを選択
    → これでログイン時に友だち追加を促せるようになります（未設定だと通知が誰にも届きません）

### 3-6. 【重要】公開ステータスを切り替える

LINEログインチャネルは作成直後 **「開発中」** で、この状態では
**チャネルの Admin または Tester 権限を持つ人しかログインできません**。

- 運営内でのテスト段階 → 「開発中」のまま。テストする人を **チャネル設定 → 権限管理** で Tester に追加
  （テスターは**ビジネスIDとLINEアカウントの連携**が必要です）
- 一般の九大生に開放する時 → **「公開済み」** に変更

> ⚠️ **「公開済み」にすると「開発中」には戻せません。** 切り替えは本番公開のタイミングで行ってください。

### 3-7. Vercel に環境変数を設定

Settings → Environment Variables に登録（**Production と Preview の両方**にチェック）:

| 変数名 | 取得元 |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | 自分で決める（**末尾スラッシュなし**） |
| `LINE_LOGIN_CHANNEL_ID` | LINEログインチャネル → チャネル基本設定 |
| `LINE_LOGIN_CHANNEL_SECRET` | 同上 |
| `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` | Messaging APIチャネル → Messaging API設定 |
| `LINE_MESSAGING_CHANNEL_SECRET` | Messaging APIチャネル → チャネル基本設定 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API |

設定後は **Redeploy が必要**です（環境変数は次のデプロイから反映）。

> ⚠️ **コールバックURLは完全一致**が必要です。Vercelのプレビューはデプロイごとにドメインが変わるため、
> `NEXT_PUBLIC_SITE_URL` に**固定のURL**（本番ドメイン、またはブランチ固定URL
> `https://<project>-git-<branch>-<team>.vercel.app`）を入れ、その URL をコールバックにも登録してください。

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` は **RLSを無視して全データを操作できる強力なキー**です。
> `NEXT_PUBLIC_` を付けない（クライアントに露出させない）こと、GitHubにコミットしないことを厳守してください。
> 本アプリでの用途は「LINEログイン時のセッション発行」と「通知対象の抽出」の2つに限定しています。

### 3-8. Supabase で SQL を実行

SQL Editor で `supabase/supabase_migration_v7_line.sql` を実行（v5実行済みが前提）。

## 4. 動作確認

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 九大メールでログイン → プロフィール | 「LINEと連携する」カードが表示される |
| 2 | 「LINEと連携する」をタップ | LINEの同意画面 → **友だち追加の確認画面** → プロフィールに戻り「LINE連携済み」 |
| 3 | ログアウト → ログイン画面 | 「LINEでログイン」ボタンが出る |
| 4 | 「LINEでログイン」 | パスワードなしでログインできる |
| 5 | 未連携の別LINEアカウントで 4 を実行 | 「まだ連携されていません」と案内が出る |
| 6 | プロフィールで興味分野に「プログラミング」を設定 | 保存できる |
| 7 | 管理者が「プログラミング」タグのクエストを承認 | 数秒でLINEに通知カードが届く |
| 8 | 通知トグルをOFF → 再度承認 | 通知が届かない |
| 9 | 公式アカウントをブロック → 承認 | エラーにならず、その人には送られない |

> 2で友だち追加の確認画面が出ない場合は、3-5の「リンクされたLINE公式アカウント」が未設定です。
> （コード側は `bot_prompt=aggressive` で、同意画面の後に友だち追加の確認画面を出す設定にしています）

## 5. 通知の仕様と費用

- **送信タイミング**: 管理者がクエストを**承認した時**（申請時ではない）
- **送信対象**: 興味分野が一致 かつ 連携済み かつ 通知ON かつ 友だち追加済み の人（依頼者本人は除く）
- **一致の判定**: 興味分野のラベルが「クエスト種別と一致」「タグと一致」「タイトルに含まれる」のいずれか
- **上限**: 1クエストあたり200人（`src/lib/quest-notify.ts` の `MAX_RECIPIENTS`）
- **送信方法**: multicast（1回のAPIで最大500人）

### 料金プラン（2026年8月時点）

| プラン | 月額 | 無料メッセージ通数 |
|---|---|---|
| **コミュニケーション** | ¥0 | **200通** |
| ライト | ¥5,000（税別） | 5,000通 |
| スタンダード | ¥15,000（税別） | 30,000通（超過分は従量課金） |

**通数のカウント対象は「配信」**です。本アプリの通知は multicast なので**1人につき1通**消費します
（例: 30人にマッチ通知 = 30通）。一方、**1対1チャット・応答メッセージ・あいさつメッセージ・Reply API は課金対象外**です。

無料枠が厳しくなってきたら:
1. ライトプランへ変更、または
2. 即時通知をやめて**1日1回のダイジェスト配信**（カルーセルで複数件まとめる）に変更 ← コード改修が必要

## 6. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 連携ボタンを押すと「LINE連携は準備中です」 | `LINE_LOGIN_CHANNEL_ID` / `SECRET` が未設定。設定してRedeploy |
| LINE側で「redirect_uriが不正」 | コールバックURLの登録と `NEXT_PUBLIC_SITE_URL` が不一致 |
| **特定の人だけログインできない** | ログインチャネルが**「開発中」**のまま。その人をTesterに追加するか「公開済み」に変更 |
| 「LINE連携の有効期限が切れました」 | 同意画面で10分以上放置。もう一度実行 |
| 友だち追加の確認画面が出ない | 「リンクされたLINE公式アカウント」が未設定、または2つのチャネルが別プロバイダー |
| 連携はできるが通知が届かない | ①友だち追加しているか ②同一プロバイダーか ③通知トグルON ④興味分野が一致しているか |
| 「LINEログインは現在利用できません」 | `SUPABASE_SERVICE_ROLE_KEY` が未設定 |
| Webhookが動かない | URLが `/api/line/webhook` か、「Webhookの利用」がONか。LINE Developers の「検証」ボタンで疎通確認 |
